👾 100 个 VibeCoding 项目之 飞书任务开成 DSH 会话

更新于2026 11 01|项目VibeCoding

⚠️ 声明：本篇的文字、配图、编辑和发布，全部由 AI 完成。

10 月 27 日发过一版，后来按 0.10.0 补过几段。现在是 0.20.1。

这个项目做的事没变：飞书里的任务，在 DSH 右侧栏里排成一列，点「开工」就投进当前对话。

上一版写过的东西都还在：优先级、Session 状态灯、自动开工。插件自己的功能指南这一版按面板入口重排了一遍，分成六块——今日洞察、任务、评论同步、定时、文档写入、筛选。下面顺着这个顺序走一遍，每块配一张整界面截图，再说清它的边界。

这些 DSH 截图来自隔离测试 Web Profile，数据是本地演示的「支付中台」项目、9 条任务，不是飞书回执；飞书侧那张评论图截自真实任务详情。

🔌 授权还是交给 CLI

插件不自己接飞书 API。授权交给本机 CLI：默认是飞书官方的 lark-cli，在面板「认证」里一键装，浏览器里走一遍 OAuth，令牌由 CLI 保管和刷新，插件不另存。

公司内部的 feishu-sync-cli 收在准备卡的「高级」里，默认不引导，只有内网或私有源环境用得到。两套后端能力互通，设置里随时切。

官方后端也补全了：任务、文档、授权、评论、自定义字段、任务关系、工作区写回都走官方 Open API，不再依赖 Python 桥。唯一没对齐的是任务 v1 富文本 @：官方评论正文暂不支持，回复按纯文本发，面板会显式提示。

装法没变：DSH 里装工作区包 packages/dsh-feishu，启用它的 bundle，右侧栏点「飞书」。开工要宿主会话服务，定时要 DSH 自动化服务；缺了会明确报错，不自己替换宿主。

🧠 今日洞察：能算的本地算，判断交给模型

面板最上面是状态行：授权可用、插件版本、CLI 版本、上次同步，右边并排「配置」「认证」两个按钮。配置内容收进状态卡里展开，认证是 CLI 安装和授权步骤，两块互斥；未就绪时认证强制展开。

状态行下面是洞察卡。左边是今天的履约摘要：跟踪几条、哪条该先收尾，摘要里的 T1 可以直接点开；右边是任务状态环图，截图里已完成 1、在跑 5、未开始 3。点「展开详情」看问题清单、建议和更多图表。

顶部的「早会同步 / 诊断 / 写入评论」按需生成：早会是口述稿，诊断给问题和建议，写入评论只把摘要写到当前绑定的任务上。

边界在 token 上。完成数、完成度、偏离、停滞这些本地统计不调模型；点「诊断 / 早会同步」才调。第一次打开没有 AI 缓存时可能自动生成一次，所以「打开面板」不等于零 token。

🗂 任务卡：一张卡看清一条任务

任务区标题行写着「筛选后的条数 / 总条数」，截图里是 8/9。每张卡第一行给三样东西：P0–P3 的优先级色条和徽标、稳定的 T<n> 编号、标题；下面是当前状态（未开工 / 已绑定 / 已开工 / 已完成）、截止时间、负责人头像、开始时间、定时与预期、工作区。

再往下是依赖关系和挂着的文档：依赖是实线（前置 → 本任务 → 后置），来源是虚线（从哪条派生），两者不混。底栏「完成 / 文档 / 同步 / 评论」直接处理这条任务，低频的「挂起」和「···」收在右边。

当前会话绑定的任务会高亮并置顶，编号 T<n> 稳定保存，刷新不会重排。

「开工」和「绑定」是两件事：开工是绑定之后再把任务投进当前会话；绑定只认领当前会话并同步命名，不投递开工指令。一条任务最多绑一条会话，一条会话也只属于一条任务，重复占用会被拒绝。

工作区按 ID 存 {id, path, title}，目录改名绑定不断；同名目录不做路径后缀猜测——agent 跑错代码库，比少开一次工贵得多。

边界：列表来自本地快照，不等于飞书实时全量清单。「完成」会写回飞书完成状态并尝试归档会话；「挂起」归档并停掉这条绑定会话，在清单的「处理状态」写上「挂起」，恢复后再人工决定是否开工。

💬 评论同步：飞书手机端写的，会话里接

先看飞书这一侧。就是普通的任务评论：截图里 T8-Game 的详情页有负责人发的「测试一下评论同步功能」，和补的「回复下我的评论」。手机端和桌面端走同一条任务评论接口，手机端发的也会出现在这里，同样会被插件同步。

DSH 这边在「配置」→「同步规则」→「评论协作」。接收任务评论默认关闭，保存后生效。打开后按身份分开：

  • 任务负责人留言，选「处理请求」：评论投递到该任务绑定的 DSH 会话，由模型判断是不是工作指令，是就直接执行。
  • 其他人留言，选「仅回复」：只回答当前任务相关的问题，不允许执行代码、命令或访问其它资料。

每轮处理上限默认 5 条。回复通过出站账本关联原评论，带稳定评论 ID，避免重复发送和自循环；失败会留在「回复待发送」，可以手动重试。截图里的收件箱有 4 条：两条等待处理、一条已回复、一条回复待发送，失败原因是 reply_to_comment_id 不在同一资源下。

回复默认走 Task v2 原生回复，不含 @；要用任务 v1 富文本 @ 作者，得选旧版接口，也需要旧版评论权限，不保证通知送达。

边界：接收默认关闭，只有「同步」会扫描新评论；收件箱是只读账本，刷新不触发同步或处理。能不能 @ 到人取决于飞书接口权限和通知设置，出站账本只保证不重复发送。

⏰ 定时：说人话，落到 DSH 自动化

任务卡上点「⏰ 定时」，弹层里直接说人话：「明天下午三点」「每隔一小时」「截止前两小时」。点「预览」先算给你看，截图里是 2026-11-02 15:00 · 一次性；确认再「保存」。

它只写这条会话上的 DSH 自动化任务，到点由 DSH 把指令投进来。预览和保存走同一套时间解析，避免「预览 15:00、保存变 15:01」。

前提是先绑定会话，并且 profile 里有 DSH 自动化服务；没有会话不排期，也不退回本地。一次性触发跑完就结束，不会自动续下一次。pause/resume 不支持，会明确拒绝；免打扰、触发窗口、until、maxRuns 这些 DSH 不支持的参数保存时返回警告，不假装生效。

工作时段 09:00–19:00、午休 12:00–13:30、每日容量 360 分钟，都在「配置」→「同步规则」→「排期与定时」里改，时区默认 Asia/Shanghai。

📄 文档写入：生成一篇，而不是搬运

「配置」→「文档生成」里配的是生成文档时的写作要求，默认「零废话、主体用表格、结构用 Mermaid」，也可以改成你们团队的格式。

在任务卡点「文档」→ 生成或更新，插件把任务描述、进展和评论整理好，写进飞书文档，再把链接回填到任务的「文档」字段；卡片上的 Tag 显示标题，点开就能看。

「文档监听」是另一件事：添加要跟踪的 wiki/docx 链接，同步时抓标题、修改时间和摘要；读全文用 feishu_doc_read，默认 8000 字符，上限 20000。

边界：生成文档会调用模型并真实创建或更新飞书文档，需要相应权限；标题和链接来自飞书返回值，不在本地伪造。桥接目前支持标题、基础富文本、代码和原生表格块，Mermaid 仍是代码文本，不会自动变成图片。更新失败时还可能新建一篇替代文档，操作前先核对用途。

🔎 筛选：同组内 OR，跨组 AND

任务标题行的「筛选」展开六个维度：完成状态、处理状态、推进状态、依赖状态、优先级、工作区。每组三态：不限、只看所选、排除所选；同组内任一命中，跨组全部满足，最后再叠一个关键词搜索。

模板行是「日常 / 全部 / 项目 / ＋」。日常排除已完成和挂起，所以列表显示 8/9；全部不限；项目跟着当前会话的工作区走。「＋」新建模板，下面的「另存新方案」「保存到当前模板」「清空全部条件」「还原原始配置」「删除当前方案」各管一件事。

边界：筛选只影响面板列表，不改本地快照也不改飞书数据；规则存在当前浏览器里，换台机器要重配。

🚧 边界

截图是 0.20.1 的界面，来自隔离测试 profile 加本地演示数据：没有为了截图运行模型、开工、提交绑定或写入远端，也没重做真实授权、写回和通知的验收。截图只证明入口和本地状态。

任务列表主要来自本地快照，不等于飞书实时全量清单。面板和 API 挂在宿主同域，没有额外鉴权，别把它当公网服务。一个 DSH_HOME 只有一份 state.json，两个实例同时跑，最后写的赢。

真实验收还得在专用清单里逐项走：授权与 scope、绑定和开工、定时记录与投递、文档和关系写回、评论账本。

🌙 收尾

这是 100 个 vibecoding 项目里的一个。打开 DSH，右侧栏第一条任务上大概还挂着定时和预期。点开工之前，先看一眼它有没有前置没完成。

飞书还是那个飞书，DSH 还是那个 DSH。中间那段复制粘贴，没了。
