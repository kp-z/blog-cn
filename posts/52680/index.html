100 个 VibeCoding 项目之 飞书任务开成 DSH 会话

更新于2026 10 30|项目VibeCoding

⚠️ 声明：本篇的文字、配图、编辑和发布，全部由 AI 完成。

🚩 立 flag：实现 100 个 vibecoding 项目！

这个项目是其中一个。飞书里是任务，DSH 里是活，中间隔着一段搬运。🔁

以前：打开飞书 → 复制标题和描述 → 切到 DSH → 新建会话 → 粘贴 → 做完再复制回去 → 勾掉。一天十条，就是十次来回。

现在：DSH 右侧栏多了一个「飞书」页签，今天的任务排在里面。点「开工」，任务投进当前对话；干完，结论自己回到飞书。

搬运没了。

🧩 它长什么样

  • 面板：顶部一行状态——授权可用、CLI 版本、上次同步时间；下面是任务列表，标题旁写着「主线任务 · 6」，可以按工作区、状态、关键词筛
  • 任务卡：负责人和关注人的头像、清单名、清单自定义字段（工作区、触发条件、状态、优先级）的 chip，左侧一条优先级色条，会话那行一盏状态灯，以及「新 / 已绑定 / 已开工 / 已完成」几个徽标
  • 当前对话卡：橙色描边，标着「已开工」「当前对话」，右边还写着绑的是哪个会话
  • 还没绑任务的对话，第一张卡是「同步为飞书任务」——按最后一轮回复起一条任务，创建完自动进清单、自动绑定

📄 一条任务一篇文档

文档这条线是后长出来的，现在是我用得最多的一块：

  • 卡片里「＋ 文档」贴个链接就绑上，绑完立刻写回飞书任务的「文档」字段；绑过的卡不再显示「＋ 文档」
  • ✎ 就地改链接，✕ 解绑，绑定 / 解绑 / 改链接都立刻同步，不用再跑一轮同步
  • 「生成文档」按任务内容生成 docx；任务改名时，它生成的 docx 标题也跟着改

最后这条踩过坑：docx 没有「改标题」的开放接口，Drive 改名要个人令牌通常没有的 scope，只能改页面块里的 text（root block 就是标题）。现在再加一层 PATCH drive 兜底，但主路径还是改 text。

🔌 为什么是插件

DSH 插件分两半：服务端半体管 HTTP 路由、定时器和模型工具，Web 半体负责往右侧栏加页签。这个项目两半都写，缺一半就是残的。

后端有两套，能力对齐，面板里二选一：

  • 默认是自建的 feishu-sync-cli——公司内网那套，非公共 PyPI 包
  • 官方推荐换成飞书官方 lark-cli：npm 装、浏览器授权、凭据进钥匙串
  • 插件不绑任何租户，任何一个飞书租户都能用；令牌始终由 CLI 自己保管和刷新，插件不读不写密钥

授权也是引导式的：两步走「装 CLI → 授权体检」，任意时刻只亮一个下一步按钮。链接带有效期，也能出二维码；创建应用或登录期间面板每 6 秒静默体检一次，完成自动往前走，授权完成后自动同步一轮。应用被租户数据安全策略整体挡住（21001）时，做多少次 OAuth 都不会成功——插件先用 bot 身份探一次，被拦就直接给三条退路：换个人账号模式、换回默认后端、去开发者后台开权限。

⚙️ 一条任务的链路

  • 同步：默认 30 分钟一轮，没有 webhook；只拉未完成，可按关键词和截止日窗口过滤。文档抓标题、修改时间、摘要
  • 按时执行：插件每 30 秒巡检一次有没有到点的任务，到点立刻跑一轮同步，不用给未来任务预建空会话
  • 开工：优先在当前对话里开工，把任务档案投进提示词；只有不在会话里（独立窗口）才新建会话，自动开工则始终新建
  • 自动开工三档：关 / 只开标注过的 / 所有新任务，默认关，每轮最多一条。它会真的建会话跑一轮，花 token
  • 工作区：只认 DSH 里已登记的工作区标题或绝对路径，拼错不会乱开工，错误直接显示在任务上。算出来的工作区还会写回任务的「工作区」字段——只填空值，一轮最多补五条
  • 提示词：占位符有标题、开始、结束、截止、链接、描述、文档。老模板没写「文档」位就追加到末尾，不改原来的措辞
  • 任务名 = 会话名 = 表情 + T<n>-标题：创建、AI 起名、改名只有一处出口，同一标题永远同一个表情；面板双击改名，会话跟着改
  • 进展自动回写：每个真有进展的 turn 结束，自动往绑定的飞书任务写一条「🤖 AI 进度」评论。只认三种硬证据——改了文件、有 commit、跑了测试，闲聊不算；整体 700 字以内，同一会话 45 秒节流，失败下次补发一次

列表上方还有一张「今日洞察」卡：左边一段 AI 判断，右边一张图。第一次打开自动生成一次，之后按「日期 + 任务签名」缓存，切对话、切按钮都不重跑；输入只发摘要不发代码。

🆕 后补的几样

文章发出来之后，插件又长了几轮。飞书那边用着别扭的、DSH 这边缺一块的，后来都补了。

  • 优先级：清单里多了一个单选字段「优先级」，P0–P3。第一次用时插件自己把字段建出来、把选项灌进去；卡片左边一条色条，标题前一个实心徽标——红 P0、橙 P1、蓝 P2、灰 P3，没设过的是虚线 --，点开选「清除优先级」就删掉。选完立刻写回飞书，不用等下一轮同步，写失败本地回滚。列表排序也认它：当前对话绑的那条永远第一，其余按 P0 → P1 → P2 → P3 → 未设置。洞察的提示词里也带着它，P0 先进今天的排期。
  • 今日洞察 v2：早会卡换成对话气泡，标题行里蹲一只 20px 的猫，生成时它蹦得快一点。右边一张图，‹ › 换——状态分布、工作区分布、WIP 趋势。用哪份数据、配什么标题由 AI 挑，数值都在本地算，图上不会出现编出来的数字。右上角三个按钮：早会同步、诊断、写入评论；切按钮只换视图，要重跑点它自己的 ↻。第一次打开自动生成一次，之后按「日期 + 任务签名」缓存，切对话、切按钮都不重跑。
  • Session 状态灯：任务卡上会话那行前面多了一盏灯——蓝的呼吸是正在回复，绿实心是跑完还没看，绿淡是空闲、已看过，灰的是会话已经结束。点 Session 跳到那条对话；正在看的这条只提示一下，灰的点下去只复制 ID，宿主重启过就真找不回来了。
  • 已完成不再同步：飞书的已完成历史一概不拉。几百条旧任务会把列表撑爆，也和「今天做什么」无关；本地标完成的、以及绑过会话又在飞书里被勾掉的留着，「已完成」筛选里还能翻。没碰过的历史，得自己回飞书翻。
  • 起名更具体：AI 起名按「项目：主语 + 做了什么，为了什么」四段式写，提示词里配了正反例；预算还是 600 → 1600 两档，空结果放大一次重试。

🕳️ 踩过的坑

  • 加载期不能抛异常：客户端半体整体 try/catch，取不到服务就静默少个页签；宿主半体反过来，工具和 webServer 是骨架，缺一个直接 fail-loud。两个半体一个安静一个响亮，是刻意留的
  • 右侧栏注册口不是官方的：真正的口是 betterSidebar.registerTab，官方 sidebarRightTabs 在某些组合里根本不在客户端的模块图里，注册会静默失败。还要等 better-sidebar 比本插件晚激活，轮询到 10 秒才放弃
  • 两个实例会互相覆盖：状态文件从「按端口一份」改成「整个 DSH_HOME 一份」，首次启动从旧的多份里挑最新一份迁移。代价换了——现在两个实例同时跑，最后写的赢
  • 推理模型吃光预算：起名原来给 200 token，额度全花在 reasoning 上，结果空着回来。现在改成 600 → 1600 两档，空结果放大一次重试
  • 双击改名不能失焦保存：旁边「AI 起名」会短暂抢焦点，自动保存会用旧值把新标题盖掉。现在只有 Enter 和「保存」才提交
  • 自定义字段 scope 默认没有：默认后端下要绕一层 Python 桥复用 CLI 的 token，不另存凭据；换官方 lark-cli 后就是原生 API 调用

🚧 边界

  • 自动开工默认关：它会真的建会话、跑一轮、花 token
  • docx 不渲染 Markdown：表格和 Mermaid 是原样文本
  • 「清单名当工作区」的兜底不生效：CLI 的任务列表只回清单的 guid，不回名字
  • 文档摘要按修改时间重抓：改一个字就重抓一次全文
  • 开工没有在真实页面点过（会真建会话、真花 token），逻辑由冒烟测试用假会话服务覆盖
  • 官方 lark-cli 后端只用假 CLI 跑过集成测试：真实的 npm 安装、应用创建、用户 OAuth 依赖公司网络和飞书企业侧权限，本机还没验证

🌙 收尾

这是 100 个 vibecoding 项目里的一个。它没多出一个窗口，只是把已经开着的两个窗口之间的路修通了。

打开 DSH → 右侧栏飞书页签 → 点「开工」→ 干活 → 结论写回、勾掉。

飞书还是那个飞书，DSH 还是那个 DSH。中间那段复制粘贴，没了。
