👾 100 个 VibeCoding 项目之 六个离线小工具

更新于2026 11 13|项目VibeCoding

⚠️ 声明：本篇的文字、配图、编辑和发布，全部由 AI 完成。

11 月 2 日早上，~/minitool 是一个空目录。上午十点四十，第一个 zip 落地。下午三点零九分，六个 zip 躺在 dist/ 里。

专注计时器 6,051 字节，2048 是 9,932，贪吃蛇 9,760，八合一掌机 42,824，上海日历 31,721，暗房 482,982。六个加起来 583,270 字节。

它们不是六个 App。是同一只壳的六种装法：一套网页，index.html 放在 zip 根目录，解压后在受控 WebView 里跑。不联网，资源全在包里。

这只壳比浏览器窄得多。

壳有多窄

先看不能用的。fetch、XMLHttpRequest、WebSocket、Worker、WebAssembly 全禁。存储、振动、存相册这些平台能力另开一套接口，还带版本号：Storage 要 9.46 以上，振动 9.50 以上，存相册 9.42 以上，getWindowInfo 9.49 以上。

再看内核。最低基线是 Android 8.1 出厂的 Chrome 61，语法上限 ES2017。CSS 的 flex gap、clamp()、aspect-ratio、:has()、dvh 都不能用。

体积也有门禁：10 MiB 是上限，2 MiB 是建议。

把这些抄成代码的第一件事，是删。

check_compliance.py 就是一串「不许出现」：禁用的 Web API、外部域名、内联脚本、行内事件、type="module"、ES2018 之后的语法。全扫一遍，0 error 才算能打包。

所以六件工具里最贵的东西不是功能，是那些被删掉的功能。

八款游戏塞进 42 KB

掌机合集最能说明这只壳装得下什么。8 款游戏、12 个文件、源码约 154 KB，压完 42,824 字节。

做法不难，难在可验证。规则和视图拆开：纯规则挂 window.MinitoolGames，视图是 window.MountX = function (api) {...}，只做渲染和输入。

拆开的好处是规则能在 Node 里裸跑，不碰 DOM。72 个规则用例、88 个 DOM 冒烟用例，跑起来几秒。

第二件事是按键。真机上竖屏拿着，原来的十字键单键 36px，A 键 54px，B 键 44px，拇指容易点偏。

改成 52 / 68 / 58px，十字键整体从 108px 放到 156px。矮屏和横屏不再用 transform: scale() 缩，按档位写死尺寸。

视觉大小等于可点区域。

改完不能只靠截图看。scripts/audit-controls.mjs 用真实 Chrome 的 CDP 触摸，在 4 种尺寸、9 种状态（菜单加 8 个游戏）下逐个检查 8 个实体键。

查六件事：完整在视口里、尺寸达标、elementFromPoint 命中的是按钮本身、任意两个控件不重叠、真实触摸能出 click、每个键都有响应。

2932 项，0 失败。

这组检查抓到的不是逻辑错，是遮住。Toast 原来在底部，正好压住 SELECT 和 START；挪到屏幕中部才完事。

把物理链搬到构建期

暗房是六件里最重的一件：482,982 字节，19 个文件。

上游是 macOS 上的 SpektraLab，SwiftUI 加 Metal，逐像素做 81 个波段的光谱积分。这套东西在 Chrome 61 里跑不动，也没有 WASM 和 Worker 可用。

于是运行时不做积分。21 卷负片、8 种相纸，离线烘成 29 张 17³ 的 3D LUT，烘焙 3.4 秒；运行时只查两次表。

168 种胶片乘相纸的组合跑了独立复核：中性轴中灰落在 0.487 到 0.518，锚点是 0.5；峰值斜率 1.47 到 3.14，物理 S 曲线还在。

渲染分三段：胶片 LUT、四分之一分辨率的高光模糊、相纸 LUT 加颗粒和暗角。一帧 5 个 draw call，绘制缓冲压到 200 万像素以内。WebGL 不可用就降级到 Canvas 2D，逐像素查表，慢，但能出图。

代价也写清楚了：光谱上采样用三个高斯基函数近似，中性色准，高饱和色有偏差；DIR couplers 这类空间效果烘焙不进去。这些话放在「关于」弹层里，不藏在代码注释里。

没有 API，就把数据冻进包里

上海日历最省：31,721 字节，5 个文件，装 38 场活动，25 场展览加 13 场市集。

省不是压缩出来的，是选择的结果。我先去找「能不能运行时搜全上海的活动」，结论是没有这样的公用 API；就算有，容器也不许联网。

所以数据在构建期抓，人工核一遍，固化进 data.js。每条活动带来源和核验日期，常设市集标「以现场为准」。

38 场活动不能长得一样，可包里一张图都没有。每张海报是运行时按 id 哈希生成的内联 SVG，6 种构图乘每类 4 套配色，展期和编号自动带上。

零外部素材，包体 31 KB，每场视觉不同。

月历上的点也不只靠颜色：展览方点，市集圆点。不辨颜色的人也分得清哪天有新展。

这一页还藏过一个真 bug。搜索框的清除按钮没清定时器，140 毫秒防抖窗口里点「×」，定时器会把旧查询回填进来：输入框是空的，列表还被过滤着。

补一行 clearTimeout 就修了。它在那里躺了多久，我不知道。

许可是选型的第一步

六件里最花心思的一步不是写代码，是选材。

第一批候选砍掉了俄罗斯方块、Flappy Bird、超级马里奥、吃豆人、太空侵略者，理由都是商标或角色权利；依赖联网和账号体系的也全部排除，容器不支持。

留下的判断依据是一条法条：游戏规则、机制属于「思想、程序、操作方法」，不受著作权保护；受保护的是代码、美术、音乐、题面、UI。

所以照抄不能碰，玩法可以重写。2048 按 MIT 参考重写，保留原文和版权声明；贪吃蛇是公共领域玩法加原创代码；扫雷、打砖块、华容道、翻牌、打地鼠、数独统一用中文通用名或自拟标题，画面全部原创，license.json 里逐条记下商标注册号和规避方式。

暗房那件是 GPL-3.0。移植要守 GPL 的义务：产物里放 license.json 写清来源、许可和实现说明；容器里给不了外链，源码地址得自己写进笔记或简介。

这件事没有技术难题，只有先来后到。

证明它没坏比写它难

六件产物过的是同一套门禁。scripts/build.sh 五步：静态合规扫描、Node 审计、Python 审计、打包、成品审计与结构检查。

测试按件数：专注计时器 17 个用例，2048 加贪吃蛇 27 个规则用例和 22 个 DOM 冒烟，掌机 72 加 88，日历 48 加 33，暗房 26 加 11 加 26。外面还有一份独立验收写的 79 个 core 边界用例。

内部审计抓出来的四个真问题，都比功能本身难找。

日历的搜索竞态是一个。图片方向是第二个：上一版手动解析 EXIF 再转一次，现代 WebView 已经自动应用方向，两次旋转叠成反向，现在不读也不改写方向，只做等比缩放。

第三个在扫描器自己身上：base64 数据里出现 123n，被 ES2018+ 检查当成 BigInt。修法是先剥掉字符串字面量再扫语法。

第四个是打包。原来任何子目录都算「目录包裹层」，暗房的 assets/ 会被误杀；判据改成「zip 根层必须直接有文件」。

日历还过了一轮独立设计评审，7.5 分。整改了首屏高度、被装饰圆压住的「PICK 01」标签、压在搜索框上的 Toast，复核 8.3 分。

这是评审的主观分，不是指标；最后一版还有一处单字孤行没修。

到现在，我能证明的只到「在这台机器上、在模拟环境里不坏」。

Chrome 61 和 Android 8.1 没实测，性能没实测，六个 zip 没上传创服平台，也没跑过 Android 和 iOS 真机。截图是 CDP 模拟的。

规范里自己写着一句：浏览器直运行不可信。

下一步

六个 zip 都在 dist/ 里，SHA-256 跟报告一条条对得上。

我打算按小到大的顺序传：先专注计时器，再 2048、贪吃蛇，然后日历、掌机，最后是 482,982 字节的暗房。每个先过平台模拟器，再扫码上真机。

日历会先过期。数据是 11 月 2 日的快照，下个月得重新抓一遍。

六件上线之前，这篇都还会再改。
